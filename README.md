## 빠른 시작

```bash
npm install         # 의존성 설치
npm run dev         # 개발 서버 → http://localhost:5173
npm run typecheck   # 타입 검사 (tsc -b)
npm test            # 계산 엔진·케이스 저장·체크리스트·AI 답변 규칙 테스트
npm run build       # 타입 검사 + 프로덕션 빌드 (dist/)
npm run preview     # 빌드 결과 미리보기
```

- Node.js 18 이상, npm 사용. 데이터베이스는 없습니다.
- AI 질의응답의 직접 입력 질문은 참고문헌 RAG 서버(Python)가 켜져 있을 때만 실제 검색·AI 답변을 씁니다. 서버가 꺼져 있으면 기존 시연용 답변 매칭으로 동작합니다.

### 참고문헌 RAG 서버 (선택)

```bash
pip install -r server/requirements.txt
python scripts/build_corpus.py     # HRSG_RAG_참고문헌/*.pdf → rag/corpus.json, rag/doc_map.json
python scripts/build_indices.py    # → rag/embeddings.npy, rag/metadata.json, rag/bm25_index.pkl (CPU 약 1시간)
copy .env.example .env             # .env 에 GEMINI_API_KEY=... 입력 (Google AI Studio 키, 없으면 검색 결과만 표시)
python -m uvicorn server.app:app --port 8000
```

- 답변 생성은 Google Gemini(`google-genai` SDK)입니다. 기본 모델 순서는 `gemini-3.5-flash` → `gemini-3.8-flash`이며, 앞 모델이 과부하(503/504)·한도 초과(429)면 다음 모델로 넘어갑니다. `.env`의 `RAG_MODEL`로 바꿀 수 있습니다.
- `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다.

- `npm run dev`의 Vite 서버가 `/api` 요청을 `127.0.0.1:8000`으로 넘깁니다.
- 검색기(BGE-M3 모델 + 인덱스)는 서버 시작 시 한 번만 메모리에 올리며, 시작에 수십 초가 걸립니다.
- `rag/` 산출물은 참고문헌 원문을 담고 있으므로 커밋하지 않습니다 (`.gitignore`).
- 린트 명령은 아직 없습니다.
- Windows PowerShell에서 `npm`이 "스크립트를 실행할 수 없으므로…"로 막히면 `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`를 한 번 실행하거나 `npm.cmd run dev`를 사용하세요.

## 대시보드 / 개요

현재 평가 케이스를 요약하고 다른 화면으로 이동하는 허브입니다. 계산 결과는 계산기와 **같은 중앙 상태**를 참조하므로 값이 서로 다르지 않습니다.

- **최상단: AI 질의응답 + 질문 기록** — 아래 [AI 질의응답](#ai-질의응답-대시보드-최상단과-질문-기록) 참고. 그 아래로 기존 대시보드 콘텐츠가 같은 순서로 이어집니다.

- **상단 상태 표시**
  - 가상 운전 상태(선택 시나리오 + 배압 자동 판별)
  - 활성 경보 수: `src/lib/alarms.ts`에 **정의된 DEMO 규칙만 집계**합니다. 배압 ≥ 270 mmH₂O, 트립 시나리오 선택. 클릭하면 규칙 목록이 보입니다.
  - 데이터 기준 시점: "미정 — 시연 데이터에 측정 시점 없음"
  - 마지막 입력·계산 시각
  - DEMO 표시, "실시간 연동 아님"
- **운전 현황**: 가스터빈 모델(가상), 설비 용량, 차압 ΔP, 현재 배압, 스택 온도, 운전 상태
- **데이터 준비 현황**: 데이터 수령률, 검토 진행률, 필수 데이터 충족, 평가 가능 여부, 부족 데이터 개수
- **성능 및 경제성 요약**
  - 예상 발전 출력 손실, 예상 월간 발전 손실액
  - 세정 필요성 검토 상태: 필수 데이터가 부족하면 `추가 검토 필요`. 배압만으로 확정하지 않습니다.
  - 세정 전후 예상 효과(요약만, 상세는 "세정 전후" 메뉴로 이동)
  - 공법별 비용·편익 요약
- **최근 분석 내역**: 이 케이스에서 저장한 계산 결과 스냅샷만 표시합니다. 없으면 빈 상태 안내가 나오며, 가짜 이력을 만들지 않습니다.
- 현재 평가 케이스, 다음 추천 작업(현재 상태에서 규칙으로 도출)

## 성능·경제성 계산기

### 평가 설정
- **평가 모드**
  - **DEMO 시나리오**: 예시 계산 엔진을 그대로 씁니다.
  - **사용자 입력**: 단위 환산·산술로 정의되는 경제성만 계산합니다. 검증되지 않은 배압→출력 손실 계수(0.015)를 쓰는 항목은 `모델 미연동 · 평가 보류`로 표시합니다.
- **운전 시나리오 (DEMO 프리셋, 공학 기준 아님)**

  | 시나리오 | 현재 배압 | 차압 ΔP |
  |---|---:|---:|
  | 정상 | 255 mmH₂O | 22.0 mbar |
  | 경보 (기본값) | 320 mmH₂O | 28.6 mbar |
  | 트립 | 360 mmH₂O | 34.0 mbar |

  배압이나 차압을 직접 바꾸면 시나리오가 `사용자 지정`으로 바뀝니다. **선택한 시나리오와 배압 기반 자동 판별 상태는 별개의 필드**입니다.
- **이 결과 질문하기**: 입력이 유효하면 계산 결과 스냅샷을 만들고, AI 화면 입력창에 질문 초안과 스냅샷을 첨부합니다. 입력이 무효이면 숫자를 전달하지 않고 입력 보완을 요청합니다.
- **분석 스냅샷 저장**: 대시보드 "최근 분석 내역"에 기록됩니다.

### 입력값 (모두 DEMO 기본값, 편집 즉시 전체 갱신)
| 섹션 | 항목 | 기본값 | 단위 | 허용 범위 |
|---|---|---:|---|---|
| A. 설비 및 GT 운전 | 설비 유형 | F-class (DEMO-GT-150) | 선택 | F 150 MW / J 270 MW |
| | 설비 용량 | 150 | MW | 1–1,000 |
| | 가스터빈 부하율 | 90 | % | 1–110 |
| | 현재 배압 | 320 | mmH₂O | 0–1,000 |
| | 기준 배압 | 250 | mmH₂O | 0–1,000 |
| | HRSG 가스측 차압 ΔP | 28.6 | mbar | 0–200 |
| | 월간 가동시간 | 720 | h | 0–744 |
| B. HRSG 열역학 | 배기가스 출구(스택) 온도 | 135 | °C | 30–400 |
| | 드럼 압력 | 100 | bar | 1–250 |
| | 절탄기 출구 급수 온도 | 150 | °C | 0–400 |
| | 증발기 출구 가스 온도 | 350 | °C | 0–700 |
| | 핀치/어프로치 포인트 설계값 | (선택, 비어 있음) | °C | 0–100 |
| C. 경제성 기준 | SMP | 140 | 원/kWh | 0–1,000 |
| | 세정 비용 | 30,000,000 | 원 | 0–10,000,000,000 |
| | 정지일수 | 0 | 일 | 0–30 |
| | 추가 비용 | 0 | 원 | 0–10,000,000,000 |
| | 회수 출력 | 1.1 | MW | 0–100 |
| | 세정 후 유효 가동시간 | (파생값) | h | 월간 가동시간 − 정지일수×24 |

- 가상 모델명(DEMO-GT-150/270)과 용량(150/270 MW)은 실제 제조사·발전소 사양이 아닙니다. 대시보드·계산기·AI에 같은 값이 표시됩니다.
- **입력 검증**
  - 천 단위 쉼표를 받습니다.
  - 음수·범위 밖·빈 값(필수)·문자열은 입력란 아래에 사유를 표시합니다.
  - 잘못된 입력을 0으로 바꾸지 않습니다.
  - 그 값에 의존하는 결과는 `—`(내부 null) + `산출 불가`로 표시하고 마우스를 올리면 사유가 나옵니다. 이전 유효 결과를 남기지 않습니다.
- 각 입력란에 출처 표시가 붙습니다: `DEMO 기본값` / `수정됨 · 가상값` / `사용자 입력`.

### 결과 영역
- 핵심 KPI 4종(현재 배압 · 초과분 · 발전 손실 · 월간 손실)
- 배압 게이지: 시연용 임계값 270/300, `기준값 미확정`
- 계산 결과 카드: 배압 기반 손실과 세정 경제성을 단계별 식과 함께 **각각 별도 행**으로 보여줍니다. 표시 순서는 유효 가동시간, 추가 매출, 정지 손실, 초기 투자, 순편익, 월간 순증분 편익, 회수 기간, 손익분기입니다.
- 배압별 월간 손실 곡선: 사용자 입력 모드에서는 `모델 미연동`
- HRSG 개념도
  - 가스 흐름(회색 실선), 급수 흐름(파란 점선), 증기 흐름(주황 점선)을 구분해 그립니다.
  - `HRSG 개념도 · 시연용 · 실제 설비 도면 아님`
- Pinch/Approach: `분석 대기 — 설계 데이터 및 물성 기준 필요`. 검증된 계산 모델이 없어 값을 산출하지 않습니다.
- 세정 공법 비교: 드라이아이스 / 고압수 / **화학(약품)** 세정. 가상 데이터, 묶음 막대 + 표.
- 세정 전후 상세 분석은 [세정 전후](#세정-전후) 메뉴로 옮겼습니다. 계산기 입력값을 바꾸면 그 화면의 회수 출력·경제성·손익분기도 함께 바뀝니다.
- 데이터 인벤토리: 모든 입력·가정값·세정 데이터·계산 결과의 출처와 교체 필요 여부

## AI 질의응답 (대시보드 최상단)과 질문 기록

> **실제 AI, RAG, 기업 문서 검색은 연결되어 있지 않습니다.** 모든 답변에 `시연용 답변 · 실제 AI/RAG 미연동` 배지가 붙습니다.

대시보드에 들어가면 가장 먼저 보이는 영역입니다. 기존 AI 질의응답 화면의 대화, 추천 질문, 데이터 출처 및 신뢰성, 추가 데이터 안내, 대화 초기화를 그대로 옮겼습니다. 계산기의 "이 결과 질문하기"는 대시보드의 이 영역으로 이동합니다.

- **대화**
  - Enter 전송 / Shift+Enter 줄바꿈 (한글 조합 중 Enter는 전송 안 함)
  - 메시지별 전송 시각, 대화 초기화
  - "준비된 시연용 답변을 찾는 중…" 상태(실제 생성이 아님), 오류 안내
  - **케이스별 대화 기록**
- **추천 질문 14개 (4개 카테고리)**
  - 열역학·성능 영향(4): 배압 상승 영향, 차압 상승 원인, 스택 온도 상승 의미, 오염의 성능 영향
  - 세정 공법 및 경제성(3): 공법별 차이, 비용 비교 기준, 판단에 필요한 경제성 데이터
  - 핀치/어프로치(3): 핀치 정의, 어프로치 정의, 관련 설계·운전 데이터
  - 필요 데이터 가이드(4): 세정 판단 필수 데이터, 체크리스트 활용, 부족 데이터 확인, 세정 전후 검증 자료
- **직접 입력한 질문**: 준비된 질문과 대조합니다(`src/lib/qaMatch.ts`). 맞는 질문이 없으면 다음 문구를 표시합니다. "확인 가능한 공학 데이터 범위를 벗어났습니다. 추천 질문을 이용하시거나 계산기 화면을 확인해 주세요."
- **답변 구조**
  1. 핵심 개념 및 요약
  2. 계산기 연동 수치 요약
  3. 공학적 원인 및 근거(접기)
  4. 추가 필요 데이터: 항목별 현재 수령 상태 배지 + "체크리스트에서 보기"(해당 행으로 스크롤·강조)
  5. 출처/자료명: 확인된 출처가 없으므로 `검증된 출처 미등록`
  6. 관련 화면 바로가기
- **수치 인용 규칙**
  - 현재 케이스의 중앙 계산 엔진 결과 중 **유효한 것만** 인용합니다. 무효이면 `—`와 사유를 보여줍니다.
  - 계산기에서 넘어온 스냅샷은 그 뒤 입력이 바뀌면 숫자를 인용하지 않고 다시 질문하도록 안내합니다.
- **질문 기록** (AI 질의응답 바로 아래 카드)
  - 새 답변이 나올 때마다 질문 내용, AI 답변(①~⑥ 전체), 질문·답변 일시, 케이스 이름을 하나의 기록으로 저장합니다.
  - 답변은 **기록 시점의 내용 그대로** 저장되어, 이후 계산 입력이 바뀌어도 기록은 바뀌지 않습니다.
  - 최신순 정렬, 기록을 누르면 질문과 답변 전체 표시, 개별 삭제, 전체 삭제(확인 단계 있음), 목록 접기/펼치기·스크롤
  - "대화 초기화"는 대화 화면만 비우며 질문 기록은 지우지 않습니다. 반대로 기록을 지워도 대화는 그대로입니다.
  - 저장: localStorage 키 `hrsg.qaHistory`(최대 200건). **이 브라우저에만** 저장되며 다른 기기·사용자와 공유되지 않습니다. 기능 도입 전의 대화는 소급 기록하지 않습니다.
  - 저장 로직은 UI와 분리되어 있습니다(`src/lib/qaHistory.ts`). 서버 DB로 바꿀 때는 `QaHistoryRepository` 구현을 만들어 `setQaHistoryRepository()`로 교체합니다.

## 데이터 요청 체크리스트

- **22개 항목**: A. 가스터빈/운전 5 · B. HRSG 설계/운전 9 · C. 세정/유지보수 8. 기존 이름·id 유지.
- **표 열**: 검토 | 항목명(형식) | 필요 이유(우선순위·필수) | 측정값/단위 | 측정 위치·조건·일시 | 데이터 상태 | 메모/비고. 작은 화면에서는 카드형으로 배치됩니다.
- **수급 상태와 검토 여부는 별도로 관리합니다.**
  - 데이터 상태 드롭다운: `실측 데이터 미입력`(기본) · `요청 필요` · `수령 완료` · `검증 필요`
  - 검토 체크박스는 상태를 바꾸지 않고, 상태도 체크박스를 바꾸지 않습니다.
- **진행률 정의** (`src/lib/checklistStats.ts`, 모든 진행률 카드가 같은 함수 사용)
  - 데이터 수령률 = (수령 완료 + 검증 필요) ÷ 22 × 100. 검증 필요는 수령 후 검증 대기 상태로 수령에 포함합니다.
  - 검토 진행률 = 검토 체크 ÷ 22 × 100
  - 필수 데이터(우선순위 높음 10개) 충족 = 모두 `수령 완료`. 평가 가능 = 충족 + 필수 항목 모두 검토.
  - 하단에 카테고리 A/B/C별 진행률
- **검색·필터**: 실시간 검색, 전체 / 미수신·요청 필요 / 수령 완료(검증 필요 포함). "표시된 항목 전체 검토 선택/해제"는 **검토 체크박스에만** 적용됩니다.
- **자료 요청 이메일 초안**
  - `요청 필요` 항목을 자동으로 모읍니다.
  - 고객사/발전소명 입력란, 요청 목적, 항목별 필요 단위·측정 조건·추가 설명, 활용 목적을 포함합니다.
  - 제목·본문 편집 후 복사하면 성공/실패를 토스트로 안내합니다.
  - **발송 기능은 없으며** 발송 완료로 표시하지 않습니다.

## 케이스 관리와 로컬 저장

- **케이스 관리** (헤더 "케이스 관리"): 새 케이스, 이름 수정, 목록·선택·전환, 복제(깊은 복사), 삭제(확인 필요, 마지막 케이스는 삭제 불가)
- **케이스마다 독립적으로 관리하는 데이터**: 운전 입력값·설비 모델·평가 모드·시나리오·계산 결과(입력에서 파생)·체크리스트·실측 스냅샷·AI 대화 기록·분석 이력. 케이스 A를 바꿔도 B는 바뀌지 않습니다.
- **localStorage 자동 저장**
  - 키 `hrsg.workspace`(버전 2), 변경 후 0.25초 뒤 저장합니다. 언어·테마는 `hrsg.lang`·`hrsg.theme`, AI 질문 기록은 `hrsg.qaHistory`에 저장합니다.
  - 새로고침하면 복원됩니다.
  - 손상된 데이터는 기본 상태로 시작하고 원문을 `hrsg.workspace.corrupt`에 보관하며 안내합니다.
  - 미래 버전 데이터는 불러오지 않고, 구버전·누락 필드는 보정합니다.
  - 용량 초과·저장 불가는 헤더에 표시합니다.
- localStorage는 **이 브라우저에만** 저장됩니다. 서버 저장이나 사용자 간 동기화가 아니며, 기업 기밀 데이터는 보안 검토 전에 입력하지 않도록 화면에서 안내합니다.

## 중앙 계산식과 단위

모든 계산은 UI와 분리된 순수 함수로 `src/lib/calc.ts`에 있습니다. 화면별 파생은 `src/lib/calculatorModel.ts` 한 곳에서 합니다.

| 계산 | 식 | 단위 |
|---|---|---|
| 배압 초과분 | `deltaBP = max(0, currentBP − referenceBP)` | mmH₂O |
| 출력 손실 예시 | `powerLossMW = deltaBP × 0.015` (DEMO 임시 계수) | MW |
| 월간 손실 예시 | `monthlyLossKRW = powerLossMW × 1000 × operatingHours × SMP` | 원 |
| 유효 가동시간 | `operatingHours − shutdownDays × 24` | h |
| 추가 발전 매출 | `recoveredPowerMW × 1000 × effectiveHours × SMP` | 원 |
| 정지 손실 | `운전 출력(용량×부하율) × 1000 × shutdownDays × 24 × SMP` | 원 |
| 초기 투자 | `세정 비용 + 정지 손실 + 추가 비용` | 원 |
| 세정 순편익(첫 1개월) | `추가 매출 − 세정 비용 − 정지 손실 − 추가 비용` | 원 |
| 월간 순증분 편익 | `recoveredPowerMW × 1000 × operatingHours × SMP` | 원 |
| 단순 회수 기간 | `초기 투자 ÷ 월간 순증분 편익` (편익 ≤ 0 → 회수 불가) | 개월 |
| 손익분기 | `정지일수 + 초기 투자 ÷ (월간 순증분 편익 ÷ 30)` | 일 |

- **이중 반영 방지**
  - 정지시간은 유효 가동시간에서 빠집니다(회수 출력 없음).
  - 정지 손실은 기저 운전 출력의 기회비용으로 **한 번만** 차감합니다.
  - 일회성 비용은 초기 투자에만 넣고 월간 편익에서 다시 빼지 않습니다.
- **개념 분리**: 배압 기반 손실 추정치와 회수 출력(입력 가정값)은 같은 값으로 취급하지 않습니다.
- **기본 예시 검증값** (320 / 250 / 720 h / 140 원/kWh)
  - 초과분 **70 mmH₂O**, 손실 **1.05 MW**, 월간 손실 **105,840,000원**(자동 테스트 포함)
  - 기본 경제성: 추가 매출 110,880,000원, 순편익 80,880,000원, 회수 0.27개월, 손익분기 약 8.1일
- **손익분기 값이 바뀐 이유**: 이전 세정 전후 화면의 "24일"은 별도로 정해 둔 1,250,000원/일을 쓴 값이었습니다. 시나리오의 회수 출력 1.1 MW로 계산한 일일 편익(약 3,696,000원)과 맞지 않아, 중앙 엔진 결과(약 8.1일)로 통일했습니다.
